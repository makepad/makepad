Reproduction: make an input directory containing only the verified
Windows.Win32.winmd and WebView2.tlb above. Replace <input-dir> below with its path.
Run from the repository root; use the already installed Rust toolchain. The
generator has its own workspace and no external crate dependencies. On Windows,
append .exe to the generator executable. No SDK is needed for normal builds.
cargo build --release --manifest-path tools/winbind/Cargo.toml
tools/winbind/target/release/makepad-winbind generate-module <input-dir> tools/winbind/apis-composition.txt libs/windows/sys/src/composition.rs composition libs/windows/sys/src/lib.rs
tools/winbind/target/release/makepad-winbind generate-module <input-dir> tools/winbind/apis-web-view.txt libs/windows/sys/src/system_web_view.rs system_web_view libs/windows/sys/src/lib.rs
When CARGO_TARGET_DIR is set (e.g. a devhub lease), the executable is instead
<CARGO_TARGET_DIR>/release/makepad-winbind. Add only the two pub mod declarations
to the existing main lib.rs; do not regenerate it or its core.rs support file.

Additive session / Task Scheduler generation (M4d):
Uses only the same verified Windows.Win32.winmd (SHA-256 above); no WinRT
metadata or new SDK is required. Existing main lib.rs/core.rs are retained,
following the additive composition path, since the original WinRT inputs are
not available here. API roots are in apis.txt and the additive subset in
apis-session.txt. Run from the root with the repository's release-built tool:
<CARGO_TARGET_DIR>/release/makepad-winbind generate-module <input-dir> tools/winbind/apis-session.txt libs/windows/sys/src/session.rs session libs/windows/sys/src/lib.rs
The main lib.rs exports session and process; process.rs is handwritten std
Command configuration using generated constants, with no FFI or vtables.
